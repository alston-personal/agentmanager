# Anti-slop content and UI filter (original AgentOS adaptation)

1. Identify audience, purpose, action and existing brand/character design language.
2. Remove unsupported hype, hollow status paragraphs, repetitive transitions, fake numbers, generic introductions and conclusions.
3. Keep concrete facts, source provenance, meaningful examples and specific calls to action.
4. For UI, judge hierarchy, focus, accessibility, touch targets, mobile layout, error/loading states and product identity. Gradients, icons, animations and cards are allowed when they serve a clear purpose.
5. Compare against real screenshot/site when available; static markup alone is not a usability receipt.
6. Preserve distinctive creative voice, deliberate humor and characters; do not standardize everything into corporate blandness.
7. Only flag meaningful violations with a specific fix and a measurable acceptance check. Do not create a large stylistic refactor unrelated to the request.
8. For shipped changes also invoke anti-slop-delivery; good copy without a deployed product is not complete.

Reference concepts: https://github.com/zansxart/anti-slop and https://github.com/Krirox/anti-ai-slop-skills . Original condensed rules; upstream source text is not bundled.
